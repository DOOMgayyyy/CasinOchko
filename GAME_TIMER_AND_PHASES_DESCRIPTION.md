# Описание функционала таймера и фаз игры

## Обзор

Проект реализует игру в блэкджек с системой таймеров и управлением фазами игры через статусы комнат. Вся логика таймеров и переходов между фазами обрабатывается на сервере (PHP), клиент (React) получает обновления через polling каждую секунду.

---

## Статусы комнат

В базе данных определены 4 статуса комнаты:

1. **`waiting`** - Ожидание игроков
   - Комната создана, игроки могут присоединяться
   - Ставки не принимаются
   - Таймера нет

2. **`waiting_for_bets`** - Фаза ставок
   - Хотя бы один игрок сделал ставку
   - Игроки могут делать ставки (30 секунд)
   - Таймер отсчитывает время до начала игры

3. **`playing`** - Игра идёт
   - Карты розданы
   - Игроки делают ходы (по 15 секунд на ход)
   - Таймер отсчитывает время хода текущего игрока

4. **`closed`** - Комната закрыта
   - Игра завершена или комната удалена
   - Таймера нет

---

## Константы таймеров (сервер)

Определены в `GameLogic.php`:

```php
const BET_TIMEOUT_S = 30;      // Фаза ставок: 30 секунд
const ACTION_TIMEOUT_S = 15;   // Ход игрока: 15 секунд
const FULL_TIMEOUT_S = 600;    // Общий таймаут бездействия: 10 минут
```

## Механизм работы таймера

### Серверная часть (`gameLogic.php`)

#### 1. Метод `getTimer($room)`

Вычисляет оставшееся время на основе текущего статуса комнаты:

**Фаза ставок (`waiting_for_bets`):**
```php
if (!$room->current_member_id && $room->status === 'waiting_for_bets') {
    $timeElapsed = time() - strtotime($room->last_update);
    return max(0, self::BET_TIMEOUT_S - $timeElapsed);
}
```
- Использует `last_update` как точку отсчёта
- Возвращает оставшиеся секунды (от 30 до 0)

**Ход игрока (`playing`):**
```php
if ($room->current_member_id && isset($room->turn_start_time)) {
    $timeElapsed = time() - strtotime($room->turn_start_time);
    return max(0, self::ACTION_TIMEOUT_S - $timeElapsed);
}
```
- Использует `turn_start_time` как точку отсчёта
- Возвращает оставшиеся секунды (от 15 до 0)

**В других случаях:**
- Возвращает `null` (таймера нет)

#### 2. Метод `checkTimeouts($roomId)`

Вызывается при каждом запросе `getInfoRoom()` и проверяет истечение таймеров:

**Проверка общего таймаута (10 минут):**
```php
if ($timePassedSinceLastUpdate > self::FULL_TIMEOUT_S) {
    $this->db->updateRoomStatus($roomId, 'closed');
    $this->db->cleanRoom($roomId);
    return;
}
```

**Проверка фазы ставок (30 секунд):**
```php
if (!$room->current_member_id && $room->status === 'waiting_for_bets') {
    $betPhaseExpired = ($timePassedSinceLastUpdate > self::BET_TIMEOUT_S);
    
    if ($betPhaseExpired) {
        // Убираем игроков без ставок
        // Если есть игроки - запускаем игру (Player::startGame())
        // Если нет игроков - закрываем комнату
    }
}
```

**Проверка хода игрока (15 секунд):**
```php
elseif ($room->current_member_id && $room->status === 'playing') {
    if ($timePassed > self::ACTION_TIMEOUT_S) {
        // Автоматический пасс
        $this->db->resetCurrentMember($roomId);
        $this->db->updateRoomAction($roomId);
    }
}
```

#### 3. Важное замечание о `last_update`

```php
// Обновляем last_update ТОЛЬКО в режиме ожидания
// НЕ обновляем во время фазы ставок и игры, чтобы таймеры работали!
if ($room->status === 'waiting') {
    $this->db->touchRoom($roomId);
}
```

Это критично для работы таймеров - если обновлять `last_update` во время фазы ставок или игры, таймеры будут сбрасываться.

## Переходы между фазами

### 1. `waiting` → `waiting_for_bets`

**Триггер:** Первая ставка игрока (`Player::makeBet()`)

```php
// Если это первая ставка, переводим комнату в waiting_for_bets
if ($room->status === 'waiting') {
    $this->db->updateRoomStatus($roomId, 'waiting_for_bets');
}
```

**Что происходит:**
- Статус меняется на `waiting_for_bets`
- `last_update` фиксируется (не обновляется до конца фазы)
- Запускается таймер на 30 секунд

### 2. `waiting_for_bets` → `playing`

**Триггер:** Истечение таймера ставок (30 секунд) или все игроки сделали ставки

```php
// В checkTimeouts() при истечении таймера:
$result = $player->startGame($roomId);
```

**Что происходит в `Player::startGame()`:**
1. Пересоздание колоды
2. Раздача 2 карт каждому игроку со ставкой
3. Раздача 1 карты дилеру
4. Установка первого игрока (`setCurrentPlayer()`)
5. Смена статуса на `playing`
6. Установка `turn_start_time` для таймера хода

### 3. `playing` → переход хода

**Триггеры:**
- Игрок сделал действие (`takeUserCard()`, `pass()`, `doubleBet()`)
- Автоматический пасс при переборе (>21)
- Автоматический пасс при 5 картах
- Истечение таймера (15 секунд)

**Что происходит:**
```php
// При любом действии игрока:
$this->db->updateRoomAction($roomId); // Обновляет hash для синхронизации

// При пассе или таймауте:
$this->db->resetCurrentMember($roomId); // current_member_id = null
$this->db->updateRoomAction($roomId);
```

**Переход к следующему игроку:**
- Логика перехода реализована через обновление `current_member_id`
- При `updateRoomAction()` обновляется hash, что триггерит обновление на клиенте
- Следующий игрок определяется на клиенте или через отдельную логику

### 4. `playing` → `waiting` (новый раунд)

**Триггер:** Завершение раунда (`Player::startNewRound()`)

```php
$this->db->updateRoomStatus($roomId, 'waiting');
$this->db->setCurrentPlayer($roomId, null);
// Очистка карт, ставок, статусов игроков
```

**Что происходит:**
- Все игроки становятся `spectator`
- Ставки обнуляются
- Карты очищаются
- Комната готова к новому раунду

## Клиентская часть

### Game Loop (`Server.ts`)

```typescript
startGameLoop(roomId: number, cb: (roomInfo: TRoomInfoResponse) => void): void {
    this.gameInterval = setInterval(async () => {
        const result = await this.getInfoRoom(roomId);
        // Вызываем callback только если есть изменения
        if (result && result.changed) {
            cb(result);
        }
    }, GAME_TIMESTAMP); // 1000ms = 1 секунда
}
```

**Особенности:**
- Запрос к серверу каждую секунду
- Callback вызывается только при изменении hash
- Таймер обновляется только при изменении данных

### Отображение таймера (`Game.tsx`)

```typescript
const [timer, setTimer] = useState<number | null>(null);

// В handleGameUpdate:
setTimer(roomInfo.timer);

// В JSX:
<span className='timer-count'>
    ⏱ {timer !== null ? timer : '—'}
</span>
```

**Проблема:** Таймер обновляется только раз в секунду и только при изменении hash. Если hash не меняется, таймер "застывает" на клиенте, хотя на сервере продолжает идти.

## Ключевые моменты реализации

### 1. Синхронизация через hash

- Каждое изменение состояния обновляет `hash` комнаты
- Клиент отправляет свой `hash` при запросе
- Если hash совпадает - сервер возвращает `true` (нет изменений)
- Если hash отличается - сервер возвращает полные данные

### 2. Точки отсчёта таймеров

- **Фаза ставок:** `last_update` (фиксируется при переходе в `waiting_for_bets`)
- **Ход игрока:** `turn_start_time` (устанавливается при `setCurrentPlayer()`)

### 3. Автоматические действия

- **Таймаут ставок:** Автоматический запуск игры
- **Таймаут хода:** Автоматический пасс
- **Перебор:** Автоматический переход хода (через `shouldPass`)

### 4. Обработка ошибок

- Если нет игроков после таймаута ставок → комната закрывается
- Если не удалось запустить игру → комната закрывается
- Если комната закрыта → все таймеры останавливаются

---

## Текущие ограничения

1. **Таймер обновляется только раз в секунду** - нет плавного обратного отсчёта на клиенте
2. **Таймер "застывает"** если hash не меняется - даже если время идёт на сервере
3. **Нет обработки статусов на клиенте** - статус комнаты не используется для управления UI
4. **Нет локального обратного отсчёта** - клиент полностью зависит от сервера
